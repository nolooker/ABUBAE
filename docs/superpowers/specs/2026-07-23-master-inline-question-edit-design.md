# Master 문제 즉시 수정 기능 설계

## 목표

Supabase 회원 계정에 `master` 역할을 부여하고, Master가 실제 필기 문제풀이 화면에서 현재 문항의 질문, 보기, 정답, 해설을 바로 수정한다. 저장한 내용은 즉시 공개 문제에 반영한다. 초기 운영자는 한 명이며 별도의 승인 단계는 두지 않는다.

## 범위

### 포함

- 일반 회원과 Master가 동일한 Supabase Auth 로그인을 사용한다.
- `public.users`에 `role` 필드를 추가한다.
- 문제풀이 화면에서 Master에게만 `문제 수정` 버튼을 표시한다.
- 편집 모달에서 질문, 보기 4개, 단일·복수 정답, 해설을 수정한다.
- 저장 API가 Master 권한을 서버에서 다시 검증한다.
- 저장 성공 후 현재 문제풀이 화면에 변경 내용을 즉시 반영한다.
- 수정 시각과 수정자를 기록한다.
- 기존 2021년 1·2·3회 후보 문제를 Supabase 문제 데이터로 이전한다.

### 제외

- 일반 회원의 문제 수정 제안
- 수정 승인·반려 워크플로
- 수정 이력 복원 UI
- 여러 관리 권한 단계
- 실기 문제 편집

## 권한 모델

`public.users.role`은 `user | master`만 허용하며 기본값은 `user`다. 회원가입 시 생성되는 프로필은 항상 `user`가 된다. 클라이언트가 자신의 역할을 변경할 수 없도록 기존 본인 수정 정책을 교체하고, 닉네임·아바타처럼 허용된 프로필 필드만 별도 서버 경로에서 수정한다.

Master 지정은 초기에는 Supabase SQL Editor 또는 Studio에서 운영자가 직접 수행한다. 브라우저에 표시된 역할은 UI 편의를 위한 정보일 뿐 권한의 근거로 사용하지 않는다. 모든 쓰기 요청은 서버에서 `supabase.auth.getUser()`로 로그인 사용자를 확인하고 `public.users.role = 'master'`인지 재검증한다.

기존 `/admin/login` 마스터 코드 방식은 역할 통합 후 제거한다. `/admin`도 Supabase 로그인과 동일한 Master 검사 함수를 사용한다. 배포 환경의 기본 마스터 코드 의존성도 함께 제거한다.

## 데이터 모델

기존 `questions`와 `choices`를 공개 문제의 단일 원본으로 사용하도록 확장한다.

### users

- `role text not null default 'user' check (role in ('user', 'master'))`

### questions 추가·보강 필드

- `exam_type text not null default 'written'`
- `explanation text`
- `reviewed boolean not null default false`
- `published boolean not null default false`
- `updated_at timestamptz not null default now()`
- `updated_by uuid references public.users(id)`
- `(exam_id, exam_type, year, round, number)` 고유 제약

### choices

- 기존 `number`, `content`, `is_correct`를 사용한다.
- 한 문제에 정확히 4개 선택지를 유지한다.
- 복수의 `is_correct = true`를 허용한다.
- 선택지 번호는 1~4이고 문제별로 중복되지 않는다.

문제 공개 조회는 `published = true`인 데이터만 허용한다. Master는 검수 중인 데이터도 읽고 수정할 수 있다. 현재 300문항은 이미 사용자 문제풀이 경로에서 제공되고 있으므로 DB 이전 시 접근성을 유지해 `published = true`, `reviewed = false`로 넣는다. `reviewed = false`는 내용 검수가 끝나지 않았다는 운영 표식이며, Master가 수정·검수를 완료하면 문항별로 `reviewed = true`로 전환할 수 있다.

## 사용자 흐름

1. 사용자가 Supabase 계정으로 로그인한다.
2. 문제풀이 서버 페이지가 로그인 사용자의 역할을 확인한다.
3. 역할이 Master이면 문제 카드 상단에 `문제 수정` 버튼을 표시한다.
4. 버튼을 누르면 현재 문항 데이터가 채워진 편집 모달이 열린다.
5. Master가 질문, 보기, 정답, 해설을 수정한다.
6. 저장 시 클라이언트 검증 후 서버 API로 요청한다.
7. 서버는 세션과 Master 역할을 다시 확인하고 전체 변경을 트랜잭션으로 저장한다.
8. 성공 응답으로 받은 공개 문항 데이터로 현재 화면을 갱신하고 성공 메시지를 표시한다.

로그인하지 않았거나 일반 회원이면 수정 버튼을 렌더링하지 않는다. 수정 API에 직접 접근하면 각각 `401` 또는 `403`을 반환한다.

## 편집 모달

모달은 현재 문항에만 집중하며 다음 필드를 제공한다.

- 질문: 여러 줄 텍스트
- 보기 ①~④: 각 여러 줄 텍스트
- 정답: 보기별 체크박스, 하나 이상 선택 필수
- 해설: 여러 줄 텍스트, 초기에는 빈 값 허용
- `취소`, `저장` 버튼

저장 중에는 중복 제출을 막는다. 닫기 전에 변경 사항이 있으면 폐기 확인을 표시한다. 오류가 발생하면 입력값을 유지하고 모달 안에 원인을 표시한다.

## 서버 경계와 저장

클라이언트는 `PATCH /api/admin/written-questions/[questionId]`에 편집 값을 보낸다. API는 다음 순서로 처리한다.

1. Supabase 로그인 확인
2. `users.role` Master 확인
3. 질문·보기 개수·정답 인덱스·문자열 길이 검증
4. DB 함수(RPC)를 호출해 질문과 보기 4개를 하나의 트랜잭션으로 수정
5. `updated_at`, `updated_by` 기록
6. 수정된 공개 문항과 편집 메타데이터 반환

질문만 저장되고 선택지 저장이 실패하는 부분 성공은 허용하지 않는다. 클라이언트가 보내지 않은 `exam_id`, 연도, 회차, 문항 번호는 이 기능에서 변경하지 않는다.

## 문제 조회 전환

현재 번들 JSON은 이전 및 복구용 원본으로 남기되, 운영 문제풀이와 채점은 Supabase를 단일 원본으로 사용한다. 공개 문제 조회는 정답을 제외한 질문·보기만 반환한다. 채점 API는 서버에서 같은 DB의 정답을 조회하므로 제출 전 정답 비공개 경계를 유지한다.

Supabase 연결 실패 시 운영 화면에서 오래된 JSON으로 조용히 대체하지 않는다. 데이터 원본이 달라져 잘못 채점될 수 있으므로 명확한 오류 상태를 표시한다. 로컬 콘텐츠 검증 도구는 JSON과 시드 데이터의 구조 검증에 계속 사용한다.

## 오류 처리

- `401`: 로그인 필요
- `403`: Master 권한 없음
- `404`: 대상 문항 없음
- `400`: 질문 공백, 보기 4개 불충족, 정답 없음, 잘못된 정답 인덱스
- `409`: 수정 중 대상 문항이 다른 요청으로 변경됨
- `500`: 트랜잭션 실패 또는 DB 오류

동시 수정 충돌을 감지하기 위해 요청에 기존 `updated_at`을 포함하고 DB 값과 다르면 `409`를 반환한다. 초기 운영자가 한 명이어도 여러 탭에서 오래된 내용을 덮어쓰는 문제를 방지한다.

## 보안

- Master 역할은 `user_metadata`가 아니라 서버가 관리하는 `public.users.role`을 기준으로 한다.
- 서비스 역할 키는 브라우저에 전달하지 않는다.
- 공개 RLS 정책은 Master 쓰기 권한과 분리한다.
- API와 DB 정책 모두에서 권한을 검증한다.
- 수정 API는 허용된 필드만 명시적으로 받아 대량 할당을 방지한다.
- 기존 `ADMIN_MASTER_KEY` 기본값과 `/admin` 경로 전용 쿠키 인증은 제거한다.

## 테스트 기준

### 단위·컴포넌트

- Master에게만 수정 버튼이 표시된다.
- 모달에 현재 질문·보기·복수 정답·해설이 채워진다.
- 질문 공백, 보기 누락, 정답 없음은 제출할 수 없다.
- 저장 성공 시 현재 문항이 즉시 갱신된다.
- 저장 실패 시 입력값과 모달이 유지된다.
- 변경 중 닫기를 시도하면 폐기 확인이 표시된다.

### API·권한

- 비로그인 요청은 `401`이다.
- 일반 회원 요청은 `403`이다.
- Master의 유효한 요청만 저장된다.
- 복수 정답이 그대로 저장되고 채점된다.
- 일부 저장 실패 시 질문과 선택지가 모두 롤백된다.
- 오래된 `updated_at` 요청은 `409`다.

### 통합·브라우저

- Master 로그인 → 문제 열기 → 수정 → 즉시 화면 반영
- 일반 회원과 비회원 화면에는 수정 진입점이 없음
- 수정 후 제출 채점이 새로운 정답 기준을 사용
- 새로고침 후에도 수정 내용 유지

## 구현 순서

1. 역할·문제 스키마 및 RLS 마이그레이션
2. 2021년 300문항 시드 생성과 검증
3. Supabase 기반 문제 조회·채점 전환
4. 공통 Master 권한 검사와 기존 Admin 인증 교체
5. Master 전용 수정 API와 트랜잭션 함수
6. 문제풀이 편집 버튼·모달·즉시 갱신
7. 전체 테스트, 브라우저 검증, 배포 환경변수·마이그레이션 확인

## 완료 조건

Master 계정으로 로그인한 운영자가 필기 문제풀이 화면에서 질문·보기·정답·해설을 수정하고, 저장 직후 같은 화면과 이후 채점에 변경 내용이 반영된다. 일반 회원과 비회원은 UI와 API 양쪽에서 수정할 수 없으며 기존 무료 문제풀이 흐름은 유지된다.
