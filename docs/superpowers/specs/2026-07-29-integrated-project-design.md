# ABUBAE 2026 통합 프로젝트 설계서

- 작성일: 2026-07-29
- 목표일: 2026-12-31
- 주당 투입 가능 시간: 약 10시간
- 대상 서비스: 정보처리기사 학습 서비스 ABUBAE
- 문서 목적: 개인 프로젝트 관리와 개발 인수인계에 함께 사용하는 기준 문서
- 상태: 설계 승인 완료

## 1. 문서의 역할

이 문서는 제품 범위, 화면, 사용자 흐름, 데이터와 보안, 일정, 콘텐츠, 수익화, QA 및 운영 기준을 하나로 연결한다.

기능은 아래 순서로 추적한다.

```text
기능 ID → 제품 정의 → 화면 → 사용자 흐름 → 데이터·권한 → 테스트 → 일정 → 완료 증거
```

코드나 화면이 존재한다는 이유만으로 기능을 완료 처리하지 않는다. 각 기능은 이 문서의 완료 정의를 충족하고 검증 증거가 있어야 완료다.

### 1.1 통합 문서 체계

| 번호 | 문서 영역 | 핵심 질문 |
|---|---|---|
| 00 | 프로젝트 마스터 인덱스 | 지금 어디까지 왔고 다음 할 일은 무엇인가? |
| 01 | 현황·갭 분석 | 완료, 부분 완료, 미구현, 오류는 무엇인가? |
| 02 | 제품·기능 정의 | 무엇을 누구에게 어디까지 제공하는가? |
| 03 | 화면 설계서 | 어떤 화면과 상태가 필요한가? |
| 04 | 사용자·관리자 흐름 | 역할별로 어떻게 이동하고 작업하는가? |
| 05 | 시스템·데이터·보안 | 데이터와 권한을 어떻게 보호하는가? |
| 06 | 로드맵·간트 | 언제 무엇을 완료하는가? |
| 07 | 콘텐츠·수익화 | 문제, 해설, PDF와 판매를 어떻게 준비하는가? |
| 08 | QA·출시·운영 | 무엇을 검증해야 출시할 수 있는가? |

## 2. 제품 목표와 범위

### 2.1 2026년 목표

2026년 12월 31일까지 다음 상태를 만든다.

1. 정보처리기사 필기 무료 MVP가 운영 URL에서 안정적으로 동작한다.
2. 최근 5개년의 실제 공개 회차 문제, 정답, 해설이 검수되어 제공된다.
3. 비회원도 전체 문제풀이 과정을 이용할 수 있다.
4. 회원은 응시 이력과 오답노트를 저장할 수 있다.
5. Master는 문제와 공지를 관리할 수 있다.
6. `정보처리기사 필기 핵심 요약 PDF`를 스마트스토어에서 4,900원에 판매한다.
7. 첫 유입, 판매, 오류 지표를 기록하고 2027년 자체 결제 도입 여부를 판단한다.

### 2.2 무료 MVP

무료 MVP의 사용자 경로는 다음과 같다.

```text
자격증 선택
→ 필기·실기 선택
→ 연도·회차 선택
→ 문제 풀이
→ 미응답 문항 경고
→ 사용자 확인 후 제출
→ 회차 종료 후 일괄 채점
→ 점수·정답·해설·회차 결과 확인
```

무료 제공 범위:

- 정보처리기사 필기
- 최근 5개년의 데이터가 있는 모든 실제 회차
- 문항과 4개 선택지
- 이전 문제, 다음 문제, 문항 바로가기
- 답안 자유 변경
- 미응답 문항 경고 후 제출 허용
- 회차 종료 후 일괄 채점
- 점수, 정오답, 과목별 결과
- 정답과 아부배 방식 해설
- 같은 회차 다시 풀기

실기는 필기와 구분해 표시하되 필기 MVP 완료 후 별도 범위로 구현한다.

### 2.3 비회원과 회원의 경계

| 기능 | 비회원 | 로그인 회원 |
|---|---:|---:|
| 전체 공개 회차 풀이 | 가능 | 가능 |
| 채점·정답·해설 확인 | 가능 | 가능 |
| 현재 회차 결과 확인 | 가능 | 가능 |
| 응시 이력 저장 | 불가 | 가능 |
| 선택 답안 저장 | 불가 | 가능 |
| 오답노트 | 불가 | 가능 |
| 재응시 점수 변화 | 불가 | 가능 |

비회원 답안과 결과는 현재 브라우저 메모리에서만 유지한다. 서버, 쿠키, `localStorage`, `sessionStorage`, IndexedDB에는 저장하지 않는다. 새로고침하거나 페이지를 떠나면 사라질 수 있음을 안내한다.

문제, 정답, 해설 접근을 로그인이나 결제로 제한하지 않는다. 로그인은 기록 저장을 위한 선택 기능이다.

### 2.4 초기 수익화 범위

- 첫 상품: 정보처리기사 필기 핵심 요약 PDF
- 판매가: 4,900원
- 초기 판매 채널: 스마트스토어
- 사이트 역할: 상품 대상, 구성, 샘플과 구매 경로 안내
- 사이트 자체 결제: 2026년 범위 제외
- 2027년 검토: 판매 데이터에 따라 자체 결제와 추가 상품 도입

## 3. 사용자 및 관리자 흐름

### 3.1 비회원

1. 자격증과 필기를 선택한다.
2. 연도와 회차를 선택한다.
3. 문제를 풀고 문항 간 이동을 한다.
4. 미응답 문항이 있으면 경고를 확인한다.
5. 돌아가서 답하거나 미응답을 오답으로 제출한다.
6. 일괄 채점 결과, 정답과 해설을 확인한다.
7. 결과 화면에서 기록 저장을 원하는 경우 로그인을 안내받는다.

### 3.2 로그인 회원

비회원 흐름을 모두 이용하고, 제출 시 다음 데이터를 본인 계정에 저장한다.

- 시험, 연도, 회차
- 응시 시작 및 제출 시각
- 문항별 선택 답안
- 정답 여부
- 총점과 과목별 결과
- 재응시 회차

틀린 문항은 오답노트에서 선택 답안, 정답, 해설과 함께 다시 확인한다.

### 3.3 Master

초기 Master 계정은 `seoteang@gmail.com`이다. 이메일은 초기 역할 지정에만 사용하고 실제 권한 판정은 `public.users.role = 'master'`로 수행한다.

문제 관리:

```text
/admin
→ 문제 관리
→ 신규 작성 또는 기존 문제 수정
→ 질문·보기·정답·복수 정답·해설 검증
→ 실제 풀이 화면 검수
→ 즉시 공개 반영
```

공지 관리:

```text
/admin
→ /admin/notices
→ 공지 작성 또는 수정
→ 초안·게시 상태 변경
→ 게시된 공지만 홈페이지와 상세 화면에 자동 표시
```

즉시 반영을 유지하되 운영 안정화를 위해 변경 전후 값, 수정자, 수정 시각을 남기는 감사 이력을 추가한다.

## 5. 시스템·데이터·보안

### 5.1 구조

```text
비회원 / 회원 / Master 브라우저
                ⇅
          Next.js 애플리케이션
   공개 화면 · 인증 · 사용자 API · 관리자 API
                ⇅
               Supabase
        Auth · PostgreSQL · RLS · RPC
```

Next.js 서버에서 세션, 역할과 입력값을 검증한다. 최종 데이터 권한은 Supabase RLS와 Master RPC에서 다시 검증한다.

### 5.2 데이터 영역

| 영역 | 대표 데이터 | 접근 원칙 |
|---|---|---|
| 공개 시험 | `exams`, `questions`, `choices` | 읽기는 전체 공개, 변경은 Master 전용 |
| 개인 학습 | attempts, answers, wrong notes | 로그인 사용자 본인의 행만 접근 |
| 공개 콘텐츠 | `posts`, `resources` | 게시된 데이터만 공개, 초안은 Master 전용 |
| 사용자·권한 | `auth.users`, `public.users` | Auth ID 연결, 본인 프로필과 역할 정책 적용 |

학습 기록 테이블의 실제 이름과 관계는 구현 계획 작성 전에 현재 스키마를 감사한 뒤 확정한다. 기존 테이블과 충돌하는 새 이름을 추정해서 만들지 않는다.

### 5.3 환경 변수

브라우저 사용 가능:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

서버에서만 사용:

- `SUPABASE_SERVICE_ROLE_KEY`
- 배포와 운영을 위한 기타 비밀 값

`SUPABASE_SERVICE_ROLE_KEY`는 클라이언트 코드, `NEXT_PUBLIC_` 변수, Git, 화면 또는 로그에 노출하지 않는다. 이전 대화나 로컬 기록에 노출된 비밀 값은 운영 전 회전 여부를 점검한다.

### 5.4 Master 변경 방어선

```text
로그인 세션 확인
→ 서버에서 role=master 확인
→ 입력값 검증
→ Master 전용 RPC에서 역할 재확인
→ 트랜잭션 반영
→ 성공한 결과만 화면에 표시
```

서비스 역할 클라이언트는 인증과 Master 권한이 확인된 뒤 서버 전용 코드에서만 생성한다.

### 5.5 Supabase 운영 원칙

- `supabase-setup.sql`을 단일 운영 설정 경로로 유지한다.
- `CREATE TABLE IF NOT EXISTS`와 `ADD COLUMN IF NOT EXISTS`로 재실행 가능하게 만든다.
- 샘플 시험은 `ON CONFLICT DO NOTHING`을 사용한다.
- 정책과 트리거는 의도한 대상을 제거한 뒤 다시 만든다.
- 기존 사용자, 문제, 선택지와 게시물 데이터를 보존한다.
- 중복 데이터나 호환되지 않는 스키마는 자동 삭제·병합하지 않고 중단 후 명시적으로 처리한다.
- 파괴적 SQL 실행 전 대상, 백업과 복구 방법을 확인한다.

## 6. 콘텐츠 설계

### 6.1 최근 5개년 기준

목표 범위는 2021~2025년 정보처리기사 필기다. 각 연도의 실제 공개 회차만 제공한다.

현재 알려진 초기 원본은 2021년 1·2·3회 PDF이며 총 300문항이다. 이후 코드와 Supabase에 반영된 실제 수량은 구현 상태 감사에서 다시 측정한다. 검수하지 않은 연도나 회차를 완료로 표시하지 않는다.

### 6.2 문제·해설 품질 절차

```text
원본 확보
→ 문항·보기·정답 추출
→ 구조·중복·범위 자동 검사
→ 원본 대조
→ 아부배 방식 신규 해설 작성
→ 정답·해설 사람 검수
→ reviewed/published 판정
→ Supabase 반영
→ 실제 문제풀이 화면 재검수
```

아부배 방식 해설:

1. 정답 번호와 정답 문구
2. 비전공자도 이해할 수 있는 핵심 설명
3. 각 오답 선택지가 틀린 이유
4. 시험장에서 기억할 핵심 포인트
5. 필요한 경우 암기 팁

복수 정답 문항은 단일 정답으로 임의 변경하지 않는다. 사용자는 하나의 보기를 선택하며 선택값이 허용 정답 목록 중 하나이면 정답 처리한다.

### 6.3 PDF 상품

`정보처리기사 필기 핵심 요약 PDF`는 문제풀이 서비스의 신뢰를 바탕으로 판매한다.

최소 구성:

- 대상 독자와 사용 방법
- 과목별 핵심 개념
- 자주 출제되는 비교·암기 항목
- 빈출 함정과 오답 포인트
- 시험 직전 체크리스트
- 사이트의 무료 기출문제 연결

출시 전 내용 정확성, 가독성, 파일 열림, 모바일 보기, 샘플 페이지, 상품 설명과 실제 구성 일치를 검수한다.

## 7. 2026 로드맵

### 7.1 실행 방식

개발, 문제·PDF 콘텐츠, 운영·수익화를 세 트랙으로 병렬 진행한다. 사용자는 주 10시간을 아래처럼 배분한다.

| 활동 | 주간 시간 |
|---|---:|
| 문제·해설 검수 | 4시간 |
| PDF 제작 | 3시간 |
| 운영·블로그·스토어 | 2시간 |
| 의사결정·실제 화면 QA | 1시간 |

Codex는 코드 구현, 자동 검사, 현황 감사와 문서화를 보조한다.

## 8. QA·배포·운영

### 8.1 표준 출시 흐름

```text
기능 정의와 완료 조건
→ 작은 단위 순차 구현
→ lint·type check·test·build
→ 비회원·회원·Master 실제 화면 QA
→ 문서와 함께 Git 커밋·병합·푸시
→ Preview 검수
→ Production 배포
→ 배포 직후 핵심 경로 점검
```

### 8.2 출시 전 필수 QA

- 문제 정확성: 문항, 보기, 단일/복수 정답, 해설
- 풀이 흐름: 선택, 이동, 바로가기, 미응답 경고, 제출, 결과
- 인증: 가입, 이메일 확인 정책, 로그인, 로그아웃, 복구, 리다이렉트
- 권한: 비회원, 회원, Master와 RLS 경계
- 데이터: 저장, 조회, 재응시와 본인 데이터 분리
- 반응형: 모바일과 데스크톱 핵심 경로
- 콘텐츠: 게시 공지만 노출, PDF 링크와 가격 일치
- 배포: 환경 변수와 운영 URL 핵심 경로

### 8.3 오류 우선순위

| 등급 | 기준 | 처리 |
|---|---|---|
| P0 | 데이터 유실, 비밀 노출, 권한 우회, 전체 서비스 불가 | 출시·운영 즉시 차단 |
| P1 | 채점·정답 오류, 로그인 실패, 핵심 이동 불가 | 출시 전 해결 |
| P2 | 일부 화면 오류, 불편한 UX, 운영 기능 누락 | 계획된 일정 내 해결 |
| P3 | 문구·디자인, 선택적 편의 개선 | 백로그 관리 |

### 8.4 운영 중 오류 대응

```text
오류 접수와 재현 정보 확보
→ P0~P3 분류
→ 데이터 흐름 기반 원인 분석
→ 회귀 테스트 작성
→ 단일 수정
→ 전체 검증
→ 재배포
→ 변경·운영 문서 갱신
```

## 9. 완료 정의

각 기능은 아래 다섯 항목을 모두 충족해야 완료다.

1. 동작: 정상 및 예외 경로가 요구사항대로 동작한다.
2. 권한: 비회원, 회원, Master 접근 경계가 검증된다.
3. 데이터: 저장, 조회, 수정 결과와 RLS가 검증된다.
4. 테스트: 자동 검사와 실제 브라우저 검수 증거가 있다.
5. 문서: 기능 ID, 사용법, 환경과 운영 주의사항이 최신이다.

상태 판정:

- 완료: 다섯 조건을 모두 충족
- 부분 완료: 화면이나 핵심 코드가 있으나 조건 일부 누락
- 미구현: 핵심 경로가 없음
- 오류: 기존 경로가 정의와 다르게 동작
- 차단: 사용자 결정, 외부 계정 또는 환경 변경 없이는 진행 불가

## 10. 역할과 사용자에게 남는 일

### 10.1 Codex가 보조·자동화할 일

- 프로젝트 실행과 구현 상태 감사
- 미완성 기능, 오류, 위험 목록 최신화
- 코드 구현과 자동 테스트
- SQL, 기능 정의서, 화면 정의서, 일정과 운영 문서 관리
- 승인된 범위의 커밋, 병합, 푸시와 배포 검증
- 실제 브라우저 핵심 경로 검수

Codex 작업은 사용자의 승인 범위 안에서 진행하며 계정 정책, 가격, 실제 출시처럼 사업상 최종 결정이 필요한 행동을 임의로 확정하지 않는다.

### 10.2 사용자가 직접 하거나 최종 승인할 일

- 문제, 정답과 해설의 내용 정확성
- 제공 가능한 원본 자료와 사용 권한
- Supabase, 배포, 스마트스토어 계정의 소유자 설정
- 비밀 값 등록과 필요한 경우 키 회전
- PDF 최종본과 판매 상세 페이지
- 가격, 환불, 고객응대와 사업 관련 정책
- 실제 공개·판매 시점과 우선순위 변경

사용자가 처음부터 끝까지 모든 기술 작업을 직접 관리할 필요는 없다. 다만 내용 정확성, 외부 계정과 사업 정책은 소유자의 판단이 필요하다.
