# 기출문제 공개 풀이 및 회원 기록 설계

## 목표

모든 방문자가 로그인 없이 전체 기출문제를 풀고 채점과 해설을 확인할 수 있게 한다. 로그인한 회원에게만 풀이 이력, 회차 결과, 오답노트, 즐겨찾기, 이어 풀기 기능을 제공한다.

## 접근 정책

### 비회원

- 모든 자격증, 연도, 회차의 공개 기출문제를 열람할 수 있다.
- 답안을 선택하고 즉시 채점할 수 있다.
- 채점 후 정답과 해설을 확인할 수 있다.
- 한 페이지에 머무는 동안에는 현재 선택과 채점 결과를 화면에 유지한다.
- 페이지 이동, 새로고침, 브라우저 종료 후에는 풀이 상태를 복원하지 않는다.
- 선택 답안, 정답 여부, 진행률을 서버나 브라우저 저장소에 저장하지 않는다.
- 채점 후 `로그인하면 풀이 기록과 오답노트를 저장할 수 있어요` 안내를 표시한다.

### 회원

- 비회원에게 제공되는 공개 학습 기능을 모두 사용할 수 있다.
- 문제를 채점할 때 선택 답안과 정답 여부를 자동 저장한다.
- 회차별 풀이 진행률, 점수, 정답률을 확인할 수 있다.
- 틀린 문제는 오답노트에 자동으로 포함된다.
- 문제를 즐겨찾기에 추가하거나 제거할 수 있다.
- 중단한 회차를 마지막으로 풀던 문제부터 이어서 시작할 수 있다.
- 로그인된 다른 기기에서도 같은 학습 기록을 확인할 수 있다.

## 사용자 흐름

1. 사용자가 자격증을 선택한다.
2. 연도와 회차를 선택한다.
3. 회차 문제 목록에서 풀이를 시작한다.
4. 문제별로 답안을 선택하고 `정답 확인`을 누른다.
5. 화면이 정답 여부와 해설을 표시한다.
6. 비회원에게는 로그인 유도 문구를 표시하되 다음 문제 진행을 막지 않는다.
7. 회원의 경우 채점 결과를 저장하고 회차 진행률을 갱신한다.
8. 회차 마지막 문제 이후 결과 화면을 표시한다.
9. 비회원 결과는 현재 화면에만 존재하고, 회원 결과는 마이페이지와 오답노트에 반영된다.

## 화면 구성

### 회차 선택

- 자격증명, 시험 연도, 회차, 총 문제 수를 표시한다.
- 회원에게는 기존 진행률과 `이어 풀기`를 표시한다.
- 비회원에게는 모든 회차의 `풀기` 버튼을 동일하게 제공한다.

### 문제 풀이

- 현재 문제 번호와 전체 문제 수를 표시한다.
- 답안을 제출하기 전에는 정답 표시와 해설을 숨긴다.
- 제출 후 선택 답안, 정답, 정답 여부, 해설을 표시한다.
- 채점 완료 전에는 다음 문제로 넘어갈 수 있지만, 미채점 상태임을 명확히 표시한다.
- 회원에게만 즐겨찾기 버튼을 활성화한다. 비회원이 누르면 로그인 안내를 표시한다.

### 회차 결과

- 현재 세션에서 채점한 문제 수, 정답 수, 정답률을 표시한다.
- 비회원에게는 `이 결과는 저장되지 않습니다`와 로그인 버튼을 표시한다.
- 회원에게는 저장 완료 상태, 오답 다시 풀기, 회차 다시 풀기를 제공한다.

### 마이페이지

- 최근 풀이 회차와 진행률을 표시한다.
- 회차별 점수 및 정답률을 표시한다.
- 오답 문제와 즐겨찾기 문제로 이동할 수 있게 한다.

## 컴포넌트 경계

- `QuestionPractice`: 답안 선택, 제출, 채점 결과 표시를 담당한다. 로그인 여부와 무관하게 동작한다.
- `AttemptRecorder`: 로그인한 사용자에게만 풀이 저장 Server Action을 호출한다.
- `RoundProgress`: 회원의 저장된 회차 진행률을 표시한다.
- `RoundResult`: 현재 세션 결과를 계산하고 회원 저장 여부를 구분해 표시한다.
- `LoginSavePrompt`: 비회원 채점 후 로그인 혜택을 설명한다.

각 컴포넌트는 로그인 자체를 수행하지 않는다. 인증 상태와 저장 결과는 서버에서 전달받으며, 공개 문제 풀이가 인증 서비스 장애로 중단되지 않게 분리한다.

## 데이터 모델

`question_attempts`는 회원의 채점 이벤트를 저장한다.

- `id`: 시도 식별자
- `user_id`: 회원 식별자
- `question_id`: 문제 식별자
- `exam_year`: 시험 연도
- `exam_round`: 시험 회차
- `selected_number`: 사용자가 고른 답 번호
- `is_correct`: 정답 여부
- `attempted_at`: 채점 시각

한 문제를 다시 풀면 새 시도 행을 추가한다. 최신 결과는 `attempted_at` 기준으로 조회하고, 전체 시도 이력은 학습 변화 분석에 사용할 수 있다.

즐겨찾기는 기존 `bookmarks` 테이블에서 `target_type = 'question'`으로 저장한다. 오답노트는 별도 테이블을 만들지 않고 회원별 최신 `question_attempts.is_correct = false` 결과에서 계산한다. 이후 사용자가 직접 메모를 작성하는 기능을 추가할 때만 별도 오답노트 테이블을 도입한다.

## 데이터 흐름

### 비회원 채점

1. 공개 문제 데이터가 Server Component에서 전달된다.
2. `QuestionPractice`가 브라우저 메모리에서 선택 답안을 관리한다.
3. 제출 시 공개 정답 데이터와 비교해 결과를 표시한다.
4. 네트워크 저장 요청을 보내지 않는다.

### 회원 채점

1. 공개 문제 풀이 과정은 비회원과 동일하게 즉시 반응한다.
2. 제출 후 Server Action이 서버에서 현재 사용자를 다시 확인한다.
3. 서버가 문제 정답을 DB에서 다시 조회해 정답 여부를 계산한다.
4. `question_attempts`에 결과를 저장한다.
5. 저장 실패 시 풀이와 해설은 그대로 제공하고 `기록 저장에 실패했습니다. 다시 시도해 주세요.`를 표시한다.

브라우저가 전송한 정답 여부는 신뢰하지 않는다. 저장용 정답 판정은 반드시 서버에서 다시 수행한다.

## 오류 처리

- Supabase 설정이 없어도 공개 문제 풀이, 채점, 해설은 정상 동작한다.
- 로그인 세션이 만료된 상태에서 저장을 시도하면 공개 풀이 결과는 유지하고 로그인 안내로 전환한다.
- 기록 저장 실패는 문제 풀이를 막지 않는다.
- 존재하지 않는 자격증, 회차, 문제는 브랜드 404 화면을 표시한다.
- 선택지나 정답이 없는 불완전한 문제는 공개 목록에서 제외하고 운영 로그에 남긴다.
- 같은 제출이 중복 전송되어도 사용자에게 오류를 표시하지 않도록 요청 식별자를 사용한다.

## 보안과 개인정보

- 공개 문제 조회는 인증 없이 허용한다.
- `question_attempts`와 문제 즐겨찾기는 본인 행만 조회·생성할 수 있도록 RLS를 적용한다.
- Server Action은 쿠키 세션을 다시 검증한다.
- 비회원 식별자, 브라우저 지문, IP 기반 학습 기록을 만들지 않는다.
- 비회원 풀이 상태를 `localStorage`, 쿠키, IndexedDB에 저장하지 않는다.

## 테스트 기준

- 비회원이 모든 공개 회차에 접근할 수 있다.
- 비회원이 답안을 제출하기 전에는 정답과 해설이 보이지 않는다.
- 비회원이 제출하면 채점과 해설이 표시되고 저장 요청은 발생하지 않는다.
- 비회원이 새로고침하면 이전 풀이 상태가 사라진다.
- 회원이 제출하면 서버 검증 후 풀이 이력이 저장된다.
- 회원이 틀린 문제는 오답노트 조회에 나타난다.
- 같은 문제를 다시 맞히면 최신 결과 기준 오답 목록에서 제외된다.
- 회원의 회차 진행률과 결과가 재접속 후 복원된다.
- 다른 회원의 풀이 이력과 즐겨찾기를 조회하거나 수정할 수 없다.
- Supabase가 설정되지 않은 환경에서도 공개 문제 페이지와 프로덕션 빌드가 성공한다.

## 무료 MVP 범위

이번 범위에는 전체 공개 기출문제 풀이, 즉시 채점과 해설, 회원 풀이 이력, 회차 결과, 최신 결과 기반 오답노트, 문제 즐겨찾기, 이어 풀기를 포함한다.

결제, 구독, 모의고사 생성, 자동 학습 계획, 오답 메모 작성, 비회원 기록 복구, 관리자 전용 문제 편집기는 후속 범위로 분리한다.
