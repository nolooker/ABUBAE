# 사이트 전수 리뷰 대응 설계

> as-built 설계 문서. `docs/superpowers/specs/2026-08-05-exam-history-bookmarks-design.md` 이후, 같은 날(2026-08-05) 진행한 사이트 전체 점검과 그 후속 수정을 사후에 기록한다.

## 배경

개발 서버 + Playwright 스크린샷으로 홈/헤더/푸터/마이페이지 등 사이트 전체를 실제로 띄워보고 코드까지 함께 확인하는 리뷰를 진행했다. 발견한 항목을 심각도순으로 정리하면:

1. **(치명)** `/exam`, `/exam/[slug]`, `/quiz/daily`, `/resources` 계열이 `src/lib/data.ts`를 통해 일반(anon) 클라이언트로 `questions`/`choices`를 조회하고 있었는데, 이 테이블은 RLS 강화 작업 때 `REVOKE SELECT ... FROM PUBLIC, anon, authenticated`로 완전히 잠겨 있었다. 그래서 이 조회는 항상 실패해 `mock-data.ts`의 가짜 문제 2개로 영구히 폴백하고 있었다 — 실제로는 수천 개의 진짜 문제가 DB에 있는데도.
2. 홈 화면 PDF 상품 카드 7개 중 3개(SQLD/ADsP)가 클릭 시 404, 나머지 4개도 실제 상세 페이지와 제목/가격이 불일치.
3. "합격후기" 섹션이 "실제 합격자들의 이야기"라고 표시하지만 완전히 지어낸 후기.
4. "12,400명 학습 중" 등 신뢰 지표 숫자가 하드코딩된 가짜 값.
5. 모든 페이지 푸터의 "이용약관"/"개인정보처리방침" 링크가 `/terms`, `/privacy`로 가는데 그 페이지 자체가 없어 404.
6. `/quiz/daily`에 "DB에 등록된 문제가 있으면 실제 문제를..." 같은 개발자용 메모 문장이 그대로 노출.
7. 모바일 하단 탭바가 홈 화면에만 존재하고, "즐겨찾기" 탭이 `/mypage/bookmarks`가 아니라 `/mypage`로 연결.

사용자와 논의해 1번부터 순서대로, 그리고 우선순위가 낮거나 콘텐츠가 아직 없는 2/3/4번은 보류하기로 했다.

## 1. 실제 콘텐츠 연결 (커밋 `b033321`)

- `/quiz/daily`는 되살리는 대신 완전히 삭제했다 — 문제를 보여주며 정답을 즉시 초록하는 현재 UX 자체가, "공개 조회는 정답을 절대 내려주지 않는다"는 이 프로젝트 전역 보안 원칙과 근본적으로 맞지 않기 때문이다(사용자 확인 후 결정).
- 그 결과 `/exam/[slug]/questions/[id]`(레거시 단일 문제 상세)도 참조하는 곳이 없어져 함께 삭제했다. 실기 문제(빈칸형)를 표현할 수도 없는 구조였다.
- 아무 데서도 참조되지 않던 `src/components/home/*`(HeroSection/HomeSections/PopularResources) 죽은 컴포넌트 3개도 같이 정리했다.
- `src/lib/exam-content-stats.ts`를 새로 만들어, 이미 존재하던 `written-content.ts`/`practical-content.ts`의 회차 요약 함수를 합산해 정처기의 실제 문제 수·최신 회차를 계산한다. `/exam`(목록)과 `/exam/jeongchogi`(허브) 두 페이지가 이제 이 값을 쓴다. SQLD/컴활처럼 콘텐츠 파이프라인이 없는 시험은 0으로 정직하게 표시한다.
- `src/lib/data.ts`에서 죽은 `getQuestionsByExam`/`getQuestion`/`getDailyQuestion`과 관련 타입을 제거했다. `getExams`/`getExam`/`getResources`/`getResource`는 `exams`/`resources` 테이블이 실제로 공개 RLS를 갖고 있어 정상 동작하므로 그대로 뒀다(다만 `resources`는 테이블이 비어 있어 여전히 mock으로 폴백한다 — 이건 버그가 아니라 콘텐츠가 없을 때의 의도된 동작이다).

## 2. 약관 페이지 + 모바일 로고 버그 (커밋 `ac6acac`)

- `/terms`, `/privacy`를 표준 템플릿으로 새로 작성했다. 사업자등록번호·고객센터 연락처 등 실제 정보는 비어 있어(개인정보처리방침 10번 항목에 표시) 실제 서비스 오픈 전 법률 검토가 필요하다.
- 홈 화면 자체 푸터의 죽은 `href="#"` 링크를 실제 경로(`/notices`, `/terms`, `/privacy`)로 연결했다. "합격후기"는 실제 기능이 없어 그대로 뒀다.
- 모바일 하단 탭바의 "즐겨찾기" 링크를 `/mypage/bookmarks`로 고쳤다(이전 세션에서 만든 기능인데 링크가 갱신 안 돼 있었음).
- **모바일에서 헤더 로고가 거의 안 보이는 버그**를 찾아 고쳤다. 원인은 `next/image`에 원본 파일의 실제 크기(1915×821)를 그대로 `width`/`height`로 넘기고 있었던 것 — Next가 "이 이미지는 크게 쓰인다"고 판단해 큰 이미지를 그대로 내려보내고, 브라우저가 그걸 CSS로 20배 가까이 축소해 그리면서 얇은 선으로 된 로고가 거의 사라져 보였다. 데스크톱(62px 높이, ~13배 축소)에서는 덜 티가 나서 지금까지 발견되지 않았다. 헤더(145×62)/사이트 전체 푸터(180×77)/홈 전용 푸터(300×129), 세 군데 모두 실제 표시 크기에 맞는 값을 넘기도록 고쳐 Next가 서버에서 제대로 축소하도록 했다.

## 3. 자유게시판 카테고리 (커밋 `89a7a59`)

- "합격후기"를 지금 당장 지우거나 실제 데이터로 바꾸는 대신, 회원이 직접 후기를 남길 수 있는 통로부터 만들기로 했다(사용자 결정).
- `board_posts.category`(`free` | `review`, 기본값 `free`) 추가. 게시판 목록에 전체/자유/후기 탭, 글쓰기·수정 폼에 카테고리 선택 버튼, 목록·상세에 카테고리 배지를 추가했다.
- 홈 화면에 실제 후기를 노출하는 건 이번 범위에 넣지 않았다 — 스팸/품질 문제 때문에 관리자가 게시글 중 골라서 노출하는 승인 단계가 필요하고, 지금은 게시글이 0개라 그 단계를 만들 실익도 없기 때문이다. 후기가 쌓이면 다음 단계로 진행한다.

## 보류된 항목 (이번 범위 아님)

- PDF 상품 카드 7개(3개 404, 4개 내용 불일치) — 실제 PDF 콘텐츠가 아직 없어 사용자가 나중에 진행하기로 함.
- 홈 화면 가짜 통계("12,400명 학습 중" 등) — 후기와 마찬가지로 실제 데이터가 쌓이기 전까지는 판단을 보류.

## 테스트

- `exam-content-stats.ts`: 회차별 문제 수 합산, 최신 회차 선정(연도/회차 동점 처리), 콘텐츠 없을 때 처리를 단위 테스트로 검증.
- 게시판 카테고리: `validateBoardPostInput`(카테고리 필수/허용값), 리포지토리 삽입·수정·목록 필터, API 라우트, `BoardPostForm` 컴포넌트(카테고리 선택 후 제출 DTO) 전부 업데이트.
- 전체 스위트 652개 통과, `npm run lint` 클린, `npm run build` 성공(신규 라우트 정상 등록, 삭제된 라우트는 빌드 결과에서 사라짐을 확인) — 2026-08-05 기준.
- Playwright로 모바일/데스크톱 로고, `/exam`·`/exam/jeongchogi` 실제 통계, 게시판 탭 전환을 스크린샷으로 직접 확인.
